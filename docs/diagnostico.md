# Diagnóstico de deuda técnica y code smells

| N°  | Code smell                | Evidencia                                                                 | Ubicación                          | Impacto | Riesgo de mantenimiento                                                                                                                                               | Prioridad |
| --- | ------------------------- | ------------------------------------------------------------------------- | ---------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| 1   | Clases largas             | Clase Sistema                                                             | sistema.ts, Línea 5-873            | Alto    | Concentra toda la lógica en un solo lugar, haciendo que cualquier cambio pueda afectar funcionalidades no relacionadas                                                | Alta      |
| 2   | Lista larga de parámetros | Clase Sistema, método registrar                                           | sistema.ts, Línea 64-71            | Medio   | Hace que exista la posibilidad de pasar los argumentos en el orden equivocado y agregar un dato nuevo obliga a modificar todas las llamadas del método                | Media     |
| 3   | Código duplicado          | Clase Sistema, métodos buscarPorEstado, buscarPorTipo, buscarPorPrioridad | sistema.ts, Línea 294-500          | Alto    | Si una regla de negocio cambia, el desarrollador debe buscar y modificar la lógica en múltiples lugares                                                               | Alta      |
| 4   | Números mágicos           | Clase Sistema, método registrar                                           | sistema.ts, Línea 191              | Bajo    | Hace que la lectura del código sea más complicada y, si cambia el valor de un estado o prioridad, hay que modificar en todos los lugares donde aparece                | Baja      |
| 5   | Switch por tipo           | Clase Sistema, método plazoSegunTipo                                      | sistema.ts, Línea 34-49            | Medio   | Cada vez que se agrega un tipo de solicitud nuevo se tiene que modificar el método, violando el principio abierto/cerrado                                             | Alta      |
| 6   | Códigos de retorno        | Clase Sistema, método cargar                                              | sistema.ts, Línea 19-27            | Alto    | Se corre el riesgo de que el sistema falle más adelante y, al no lanzar el error de forma temprana, el proceso de debugging es más difícil                            | Alta      |
| 7   | Nombres poco claros       | Interfaz Solicitud                                                        | modelo.ts, Línea 28-31             | Medio   | Incrementa el tiempo que pasa el programador intentando entender el código antes de poder modificarla, además de que se puede asumir de forma incorrecta su contenido | Baja      |
| 8   | Métodos largos            | Clase Sistema, método registrar y reporte                                 | sistema.ts, Línea 64-210 y 478-654 | Alto    | Cuesta modificarlos sin romper su funcionamiento y hace más difícil elaborar los tests                                                                                | Alta      |
